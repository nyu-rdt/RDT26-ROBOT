## HOW TO RUN STATE MACHINES

### Have two separate terminal windows open

### In one of them:
```bash
cd ~/Desktop/rdt25_gcs_ws
colcon build
isb # source workspace alias shortcut
ros2 run joy joy_node
```

In another terminal in the same window
```bash
isb
ros2 run nyurdt_gcs_manual_control joystick_main 
```

In third terminal in the same window
```bash
isb
ros2 launch nyurdt_gazebo_sim launch_sim.launch.py
```

### In the second terminal window
```bash
cd ~/Desktop/rdt25_robot_ws
colcon build
isb # source global ros
ros2 run GCS_command_subscriber
```

Press the button with two overlapping rectangles to start locomotion autonomy

## Workspace Structure

```
RDT26-ROBOT/
├── src/                  # All ROS2 packages
│   ├── nyurdt_bringup/
|   ├── nyurdt_description/
│   ├── nyurdt_autonomy/
│   ├── nyurdt_command_handler/
│   ├── nyurdt_interfaces/
│   ├── nyurdt_localization/
│   └── nyurdt_slam/
├── build/                # Generated (ignored)
├── install/              # Generated (ignored)
├── log/                  # Generated (ignored)
├── .gitignore
└── README.md
```

### Rules

* Only ROS2 packages live inside `src/`
* `build/`, `install/`, and `log/` are generated by `colcon`
* Generated folders are **never committed**
* Workspace structure should remain stable

---

## Build

From repository root:

```bash
colcon build
source install/setup.bash
```

Always build from `RDT26-ROBOT/`, not from inside `src/`.

---

## Git Workflow

### Always run Git from repo root

```bash
cd RDT26-ROBOT
git pull
```

Do not run Git inside `src/`.

---

### Branching Model

* `main` → stable, buildable workspace
* Feature branches → modify files inside `src/<package>`
* Branches do **not** change workspace structure

Example:

```bash
git checkout main
git pull
git checkout -b feature/<story>
```

Work inside the relevant package:

```
src/<package>/
```

Commit and push:

```bash
git add .
git commit -m "Describe change"
git push origin feature/<story>
```

---

## Guidelines

* Every folder inside `src/` must be a valid ROS2 package
* No empty placeholder folders
* No nested repositories
* `main` must always build cleanly
